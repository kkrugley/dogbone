# Комбинированная обработка углов SafePaws: реализация и повторная проверка

Дата: 30 октября 2026. Проект: `kkrugley/dogbone`.

## Результат

**Комбинированная обработка реализована.** На одном чертеже автоматически используются обычные dogbone и T-bone. Выбор направлений учитывает соседние углы. В сложных случаях вырезы объединяются с контуром точными операциями над отрезками и дугами.

Все **39 сочетаний «лист × диаметр» на 14 соответствующих исходных листах SafePaws** прошли повторную геометрическую проверку. Это включает Ø3/3,175 мм для фанеры 3 мм и Ø3,175/4/6 мм для фанеры 6 мм. Экспортированные файлы повторно открываются без добавления новых вырезов.

Изменения реализованы в локальном проекте. Публикация на GitHub и развёртывание production в эту работу не входили. Физическая резка и CAM-симуляция не выполнялись.

## Выбранное решение

Простая замена всех dogbone на T-bone создавала бы лишние изменения там, где обычная разгрузка уже подходит. Сохранение одного типа с отклонением конфликтующих вырезов оставляло необработанные углы. Поэтому выбран комбинированный алгоритм:

1. Для каждого угла строятся варианты: обычный dogbone и T-bone в двух направлениях.
2. Динамическое программирование по замкнутой цепочке выбирает совместимые варианты. Обычный dogbone имеет приоритет, T-bone используется для устранения конфликта. Проверяются длины обеих стенок и совместное потребление общего ребра соседними вырезами.
3. Если ни одна локальная комбинация не позволяет вставить все вырезы между исходными вершинами, применяется точное объединение/вычитание окружностей по всему контуру через `@flatten-js/core`. Это покрывает короткие уступы и перекрывающиеся разгрузки. Дуги остаются дугами DXF, а не хордами.
4. Поиск расширен на непрямые внутренние углы до выбранного предела, по умолчанию 170°. Обработаны встречающиеся в этих чертежах углы около 135°.
5. Фильтр больших элементов проверяет длины локальных стенок. Он больше не исключает узкие пазы только потому, что они находятся внутри большого отверстия.
6. Если исходное вогнутое скругление меньше радиуса инструмента, добавляется круглая разгрузка с центром исходного скругления. На Cozy 3 мм это устраняет ещё два проблемных участка.

Для вырезов, пересекающих несколько исходных рёбер, используется отдельный признак `requiresBoolean`; он не означает пропуск выреза. Тип `arc-relief` обозначает разгрузку исходного малого скругления.

## Что именно проверено

Проверка не ограничивалась счётчиком вырезов:

- Сервис проверяет, может ли круглый инструмент покрыть необходимую исходную свободную область: эрозия/расширение отверстия и аналогичный расчёт снаружи детали. Для проверки в браузере используется JSTS.
- Независимый расчёт выполнен в Python с Shapely/GEOS 2.2.0. Проверялось сохранение доступности исходных пазов, а не только добавленных разгрузок.
- Во всех 39 основных сценариях отсутствуют самопересечения, новые пересечения границ разных контуров, недоступные исходные участки и невычтенные части разгрузочных окружностей выше порога проверки.
- Все 39 DXF повторно разобраны приложением: новых вырезов не добавляется.
- Экспорт хранит точные дуги через `bulge`; единицы DXF явно заданы как **миллиметры** (`$INSUNITS = 4`).

Независимая проверка дискретизирует дуги с погрешностью хорды до 0,0001 мм и считает значимыми остатки исходной площади больше 0,01 мм². Проверка внутри сервиса использует аппроксимацию до 0,001 мм, допуск по границе 0,01 мм и численный запас 0,002 мм для касающихся окружностей. Эти допуски относятся к проверке; геометрия экспортируемых дуг не масштабируется и не заменяется этими аппроксимациями.

Результаты по каждому листу: [extended-summary.json](extended-summary.json). Дополнительные 15 контрольных сценариев, включая Ø2 и Ø2,5 мм: [summary.json](summary.json).

## Неподходящая фреза и состояние интерфейса

Контрольный случай **Cozy 3 мм / Ø4 мм** правильно отклоняется: прямые участки пазов имеют ширину 3,2–3,4 мм. Добавление разгрузок не позволяет провести 4-мм фрезу через более узкую середину паза без изменения посадочного размера.

Теперь:

- Непроверенный или неподходящий результат получает статус **Needs review** вместо Ready.
- Отчёт показывает проблемы доступности, а обычный экспорт блокируется.
- Смена диаметра или пресета немедленно аннулирует старую проверку до Apply & Re-process.
- Удаление/отключение выреза повторно проверяет фактическую геометрию.
- Пакетный экспорт явно называется **Export Ready Files** и включает только проверенные файлы.
- Диагностический экспорт неполного результата возможен только через явно заданный параметр программного API; пользовательский интерфейс его не использует.

## Проверка всей пользовательской цепочки

Применён workflow `vercel:verification`: загрузка исходного DXF → выбор диаметра → обработка → отображение → скачивание → повторное открытие. Приложение работает локально в браузере, API и серверной базы данных в этой цепочке нет.

| Граница | Проверка | Подтверждение |
|---|---|---|
| Загрузка → геометрия | Оригинальные Cozy 3 мм, Cozy 6 мм, Family 6 мм | Корректные контуры и смешанные типы вырезов |
| Параметры → обработка | Ø3,175 мм и Ø6 мм | Старый результат блокируется до повторной обработки |
| Геометрия → интерфейс | Report и список вырезов | Подтверждение диаметра; одновременно присутствуют dogbone и T-bone |
| Редактирование → проверка | Отключение необходимого выреза и восстановление | Экспорт блокируется и снова разрешается |
| Экспорт → DXF | Скачивание через Chromium | Файл читается, единицы — миллиметры |
| DXF → повторный импорт | Обработанные файлы с тем же диаметром | 0 новых вырезов, проверка проходит |

| Ошибка параметров → интерфейс | Ø4 мм на 3-мм чертеже | Needs review, экспорт недоступен |

## Файлы и воспроизведение

Проверенные выходные DXF находятся в `outputs/`, отдельно по изделию и диаметру. Архив выходных файлов содержит 39 DXF и этот отчёт. В нём нет диагностических неуспешных файлов.

Из корня проекта:

```sh
npm ci
npm test
npm run build
npm run test:browser
```

Для расширенной проверки распаковать исходные архивы в `cozy3`, `cozy6`, `family6` внутри выбранного каталога, установить Shapely и выполнить:

```sh
SAFEPAWS_DIR=/path/to/safepaws EXTENDED=1 npx --yes tsx --tsconfig tsconfig.app.json scripts/audit-tool-diameters.ts
EXTENDED=1 python scripts/check-tool-diameters.py
```

Для 3-мм фанеры Ø3 мм даёт больший запас, чем Ø3,175 мм: на самом узком 3,2-мм пазе разница с Ø3,175 составляет всего 0,025 мм. Для 6-мм фанеры Ø4 мм требует меньших разгрузок, чем Ø6 мм; обе проверенные геометрические обработки проходят. Реальный диаметр инструмента, биение, компенсацию и траектории следует задать в CAM. Прочность перемычек, удержание деталей и качество реза этой цифровой проверкой не подтверждаются.
